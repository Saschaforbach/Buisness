Condition monitoring pilot project: how it works from the inside

A pilot project is not a software download. This article shows step by step what happens before, during and after the visit to your machine, what we rehearse beforehand and how a pilot ends cleanly.

Before a plant introduces condition monitoring for its CNC spindles, it rightly wants to know what it is getting into. Who comes on site, what happens at the CNC control, who has to prepare what, and how do you get out again if it does not fit. This article describes a condition monitoring pilot project with us from the inside: from the first phone call through the dress rehearsal in our lab and the day at your machine to the close-out with a data export or verifiable deletion. We only give the time frames that we can actually commit to.

Introductory call and pre-assessment: does your machine fleet fit?

It starts with an introductory call of about 20 minutes by phone or video. It serves a single question: can your machines be connected. What matters is the CNC control, its software version and the enabled options, not the size of your business.

  • Siemens: SINUMERIK 840D sl, 828D and ONE with the OPC UA option.
  • HEIDENHAIN: TNC 640, TNC 620 and TNC7 with the OPC UA NC Server. Each connected client uses one licence there.
  • Exceptions: the iTNC 530 and TNC 320 do not have an OPC UA NC Server. Only vibration measurement is possible on them. FANUC will follow in a later phase.

Today we monitor the spindle and spindle bearings. If your problems are more on feed axes, the tool changer or coolant, we will tell you in the introductory call that this is not yet part of our offer. If it does not fit, you find out in this call and not only after the visit on site. Which machines we connect is also listed on the page Spindle monitoring.

Pre-assessment per machine

After the introductory call you receive a datasheet per machine and the IT security sheet. For each machine we need one line with manufacturer, type, year of manufacture, serial number, CNC control and NC software version. In addition, photos of the nameplate and of the options or licence screen of the control. These photos save a lot of time on site, because only they show whether the required OPC UA option is actually enabled.

We also ask about:

  • other programs that already access the control via OPC UA, for example production data acquisition, MES or the machine builder's remote maintenance. On HEIDENHAIN, each of these counts against the available licences.
  • your maintenance contract. If it reserves interventions for the machine builder, such as creating users or certificates on the control, we clarify this together beforehand.
  • the network: IP address of the control, network segment, IT contact, location and power supply for the edge box.

In parallel, your IT opens the outbound connections: TCP port 8883, alternatively 443, from the edge box to our platform in Germany. No inbound connections are needed. If a firewall inspects encrypted connections by breaking them open, the edge box needs an exception there, because otherwise certificate validation fails. Details are given under Data security.

On the organisational side, we agree a non-disclosure agreement and a data processing agreement in advance. We collect machine data, not operator data. Please clarify beforehand whether your works council needs to be informed.

Dress rehearsal with our CNC control simulator

Before we travel to you, we rehearse the visit. For this we have built our own simulator that behaves like a secured SINUMERIK. It provides an OPC UA server with spindle speed, spindle load, tool, program state and alarms. A virtual measurement card supplies matching vibration signals. Both read from the same machine model, so that speed and vibration always match. Bearing damage can be deliberately introduced into the simulator and allowed to grow, in order to test the whole chain up to the alert.

In the dress rehearsal the simulator runs in encrypted mode. It then only accepts encrypted connections with a dedicated read-only user, just as it will be at your control. We use it to practise exchanging certificates, reading out the address space and starting the edge box. All variables in the simulator are read-only, and write attempts are rejected. A simulated method counts every call. This is how we prove in our end-to-end test that the edge box never calls a method.

What the dress rehearsal does not replace

The simulator imitates a CNC control, it is not one. Which signals your control offers under which path depends on the control vendor, software version, options and machine builder. We read these paths out at your machine instead of assuming them. More on this in the article Connecting SINUMERIK and HEIDENHAIN via OPC UA.

The day on site

The visit to your machine takes one day. The aim is a solid foundation, not to have everything finished in one day. Production continues in the meantime. Only your staff or the machine builder's service operate the control. We say what we need, watch and document. The process follows a fixed checklist:

  1. Arrival: safety briefing, one dedicated companion from operations or maintenance, photos of the nameplate, version and options screens.
  2. Check the network: bring the edge box into the machine network with your IT, check that the control can be reached, test the outbound connection to the platform.
  3. Read out the address space: the edge box reads the address space of the control into a table. The same read lock applies as in operation: only browsing and reading are permitted.
  4. Exchange certificates: the control's certificate is stored in the edge box, and the edge box's certificate is marked as trusted on the control by hand. We compare the fingerprint against a printout.
  5. Create a read-only user: with your approval, your staff set up a user that is only allowed to read. On Siemens with the rights to read data and alarms, without any write right.
  6. Define the signals: only signals that were found in the table and checked live with the spindle running go into the configuration. Spindle speed is mandatory.
  7. Start and check the edge box: do the values arrive on the platform? Does the control's user interface respond as quickly as without the edge box? By default the edge box polls once per second and never more often than every 0.1 s.
  8. Test a connection loss: we disconnect the edge box's internet connection, not the one to the control. The edge box buffers, and after reconnecting the data must arrive on the platform without gaps.
  9. Define the measuring points: together with you we determine the mounting points for the vibration sensor on the spindle housing and document them with photos.
  10. Wrap-up: label the edge box, photograph the installation location, short discussion of status, open points and next steps.

Some things we never do on this day: change machine parameters, NC programs, tool data or PLC values, not even on request. Attempt writes "for testing". Open inbound ports or install remote maintenance software. Carry out network scans without approval from IT. Why the edge box technically cannot write at all is explained in the article Read only: write protection on the CNC control.

Learning phase: the learned baseline of your spindle

After the visit, the pilot begins. First the system learns the learned baseline, i.e. the normal state of each of your spindles. For every combination of machine, measuring point and speed class it collects features until there are enough measurements for robust statistics. As long as a speed class is still learning, it does not generate alerts. Speeds that your machine rarely runs take correspondingly longer.

We do not give a fixed duration for the learning phase. It depends on how often and in which speed ranges your spindles run. One precondition is important: the learning phase assumes that the spindle is healthy. If damage is already present, it becomes part of the learned baseline. After a bearing replacement or spindle repair, the baseline can therefore be learned again. This action is recorded in the log. More on this in the article Learning the baseline.

Alerts, feedback and monthly report

As soon as a learned baseline is in place, every new measurement is compared with it. There are four levels: Normal, Noticeable, Warning and Alarm. An alert is only raised when a deviation persists over several consecutive measurements. Every alert states the machine, measuring point and speed, the affected feature compared with the learned baseline, the urgency and a recommended check. For a bearing finding it names the suspected component, for example the outer race. It deliberately does not state a remaining useful life.

Your feedback is the most important contribution during the pilot. For every alert, the maintenance engineer or administrator can record whether it is correct, a false alarm or unclear. The thresholds for the levels are starting values. They are calibrated with test rig data and your feedback. Without feedback an alert stays open and is visible as open in the overview.

Once a month you receive a report per machine. What a single alert looks like in the dashboard is shown in the article Explained alerts.

Close-out: data export or verifiable deletion

A pilot ends either with the transition to regular operation or with a clean exit. There are two tools for the exit.

Data export: an administrator in your plant can export all data at any time: machines, features, control values, events, learned baselines and alerts with your feedback. The format is JSON Lines, a text file with one record per line that any analysis tool can read. Every export is recorded in the log.

Deletion: the complete deletion of a customer follows a fixed sequence that cannot be shortened:

  1. First, a complete export of all the customer's data is written to a file.
  2. Then the deletion must be explicitly confirmed by entering the exact customer name. If it does not match, nothing is deleted.
  3. The deletion of all tables runs in a single transaction: either everything is deleted or nothing.

The result is a report with the number of exported rows and deleted rows per table. This makes the deletion verifiable. It is carried out by Forbach & Partners, never via the customer interface. The edge box is removed, and its access credentials on the platform are deleted along with everything else. Frequently asked questions

How does a condition monitoring pilot project work?

An introductory call of about 20 minutes, a pre-assessment per machine by email, one day on site to connect the control read-only and define the measuring points, followed by the learning phase and the pilot with alerts, feedback and a monthly report per machine.

Is anything changed on the CNC control during the pilot project?

Nothing is changed in parameters, programs or tool data. With your approval, a read-only user is created and the edge box's certificate is marked as trusted on the control. This is done by your staff or the machine builder's service. The edge box can only read.

What does our IT need to open for condition monitoring?

Outbound connections from the edge box to our platform in Germany via port 8883, alternatively 443, and via port 443 for signed updates. No inbound connections are needed. If a firewall inspects encrypted connections by breaking them open, the edge box needs an exception.

How long does the learning phase take?

That depends on how often your spindles run in which speed ranges. The system learns per machine, measuring point and speed class until there are enough measurements. We therefore do not give a blanket duration.

What happens to our data when we end the pilot?

You can export all data as a JSON Lines file. On request, we delete all of your plant's data. A complete export is created beforehand, the deletion runs in a single transaction, and a report shows the deleted rows per table.
